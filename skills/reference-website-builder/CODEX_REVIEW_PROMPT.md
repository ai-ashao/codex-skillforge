# Codex 审查提示词

请对当前目录中的 `reference-website-builder` Agent Skill 做一次严格工程审查，并直接修复明确问题。

## 预期产品行为

该 Skill 应当：

1. 只处理用户明确提供的页面 URL，不自动克隆整个域名。
2. 高保真还原页面的 UI 设计语言、布局、响应式、动画、交互和多层素材组合。
3. 允许开发阶段临时下载目标页面素材，但必须进入隔离目录、登记 Manifest，并通过统一素材映射引用。
4. 明确区分“重建完成”和“可生产发布”。存在临时素材、竞品身份、原文、metadata 或 hotlink 时，必须保持 `PRODUCTION_READY=false`。
5. 上线前必须替换或授权素材、品牌、文案和元数据，并通过自动发布门禁。
6. 保留现有项目的框架、路由、多语言、登录、积分、支付、API、Analytics、Consent、SEO 和部署结构。

## 审查目标

### 1. Agent Skills 规范

- 检查 YAML frontmatter、文件夹名、触发描述和 supporting resources。
- 检查正文是否过长、重复或存在不可执行指令。

### 2. 页面范围

- 确认默认只处理明确 URL。
- 确认不会自动 sitemap crawl、导航遍历或全站复制。
- 检查多 URL 的隔离策略。

### 3. 高保真重建可执行性

- 检查浏览器侦察、computed style、响应式、Hover、滚动、Sticky、自动播放、拖拽和多层素材提取是否足够明确。
- 检查无浏览器、目标不可访问、脏 Git 树和已有构建失败时的恢复策略。

### 4. 临时素材隔离

- 检查 `.reference-assets/`、`public/__reference__/`、统一素材映射、Manifest、Provenance 和 Replacement Checklist 的职责是否清楚。
- 检查组件是否被要求避免散落硬编码临时路径。
- 检查替换素材是否记录尺寸、裁剪、透明度、焦点、层级和动画等视觉约束。

### 5. 生产发布门禁

- 审查 `scripts/check-reference-assets.mjs` 的正确性、跨项目适用性、错误信息和退出码。
- 确认它能拦截临时目录、源码引用、临时 Manifest 状态、目标域名和品牌词残留。
- 确认不会误删文件，不会联网，不会静默修改项目。
- 检查 README 推荐的 package scripts 是否不会递归调用自身。

### 6. 现有项目保护

- 检查是否保护路由、多语言、登录、积分、支付、数据库、API、分析、Consent、SEO 和部署配置。
- 检查是否可能静默升级框架、替换包管理器或覆盖用户改动。

### 7. 权利与安全

- 确认开发期临时素材与生产发布权利被严格区分。
- 确认不允许钓鱼、欺诈性冒充、绕过访问控制、下载执行目标脚本、提取密钥或用户数据。

### 8. QA 完整性

- 检查重建 QA 与生产 QA 是否分离。
- 检查视觉、响应式、交互、键盘、无障碍、性能、SEO、业务回归、素材替换和生产门禁是否覆盖。

## 输出格式

先给出：

- 总体结论：`通过 / 有条件通过 / 不通过`
- Critical、High、Medium、Low 问题表
- 每个问题的文件、位置、原因、风险和修复建议

然后：

- 直接修改明确且低风险的问题
- 运行 `python3 scripts/validate_skill.py`
- 对 `scripts/check-reference-assets.mjs` 建立至少一个应失败和一个应通过的临时测试项目
- 展示修改摘要和验证结果
- 对需要产品决策的问题保留 TODO，不要自行扩大 Skill 范围
